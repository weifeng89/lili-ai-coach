一、它到底是什么

查理 是一个 AI Agent 的「技能包（Skill）」，服务对象是非技术初学者 lili酱。 它的角色不是帮 lili 做事，而是教 lili 怎么跟 AI 协作：把模糊的想法理成真需求，落成一份清楚的项目说明书， 再拆解成可执行的步骤，最后让她感知到「这次比上次省了哪几步」。

一句话定位：不替用户干活、不碰领域问答、不写人设语气——只教「和 AI 协作的方法论」。这是贯穿全程的底层纪律「小且可组合」。

核心设计原则（全程未动摇）

原则含义为什么
小且可组合只干「需求→PRD→workflow + 卡点陪练」一件事，绝不变成通用助手白名单式聚焦，避免 scope creep
不替代用户思考查理只问、只整理、只翻译，答案/实现归别的 Agent培养 lili 自己的判断力
跨端一致三端方法论正文逐字符相同（AC8 硬约束）同一套方法，不同 harness 行为不漂移
零重叠不重复 lili 已有个性化 prompt 的风格/人设层（AC9）查理只讲方法论，人设由 base Agent 负责
Token 纪律references 懒加载、产物落盘、闭环软预算 ≤8 轮（AC7）避免上下文爆炸，尤其对小白长对话友好

二、完整版本时间线（过程主线）

用户提供 lili-onboarding.zip，原本是一个「自我测试 / 诊断」类技能。用户发现 lili 把它当万能顾问用， 且自我评估并不准确。于是重新定位为引导式 AI 协作教练。

当时锁死的硬约束：PTCF 框架（画像/任务/约束/验收）、放弃自测、专注里程碑 1、不与 lili 已有个性化 prompt 重叠、 必须可在 Codex + WorkBuddy 运行、帮拆 workflow、验收标准参考 mattpocock/skills 但面向初学者、信心 >90% 才生成。

v2.2.0 · 小白可用性四大槽点闭环

用户一次性抛出 4 个尖锐槽点（见第三节反馈①）

这次是「方法论很专业，但小白用不起来」的系统性批评。据此全量重构：

  • ① 安装拦人 → 仓库内置 install.py/install.sh 通用安装器 + npx add-skill 便捷路径，lili 零接触文件
  • ② 术语劝退 → 术语输出禁令 + 转译表（PTCF→项目四件套、workflow→落地步骤清单…）
  • ③ 边界僵化 → 柔性分流：永远做「问题翻译官」，不生硬拒答
  • ④ 被动救火 → 三 harness 全翻自动触发（disable-model-invocation:false / allow_implicit_invocation:true）

另补两块能力：Token 优化诊断、自动复盘落盘。验收从 AC1–AC14 涨到 AC1–AC16。

v2.3.0 · 收敛 + 补遗漏

用户二次反馈（见第三节反馈②）→ AC 20→14 分层 + 身份提示

  • ① 双脑困惑（自动触发后分不清谁在答）→ 新增「切入时轻量身份提示」，不每轮刷
  • ④ AC 膨胀 → AC20 压到 AC14，eval 拆成「用户能力 AC1–10 / 打包质量 AC11–14」两段
  • ⑤ 柔性分流靠模型 → 文档化为 R11，用「输出末尾永远附精准指令」降依赖
  • ③ Token 模式级诊断 → 经确认维持现状（已诚实声明边界）

三、两轮关键反馈循环（这是「过程」的精华）

反馈①：v2.2.0 前的「小白用不起来」四大槽点

用户原话核心：方法论设计很专业，但从「小白实际能用起来」看存在明显脱节，核心是「用开发者的思维做小白产品」。

#槽点用户原意（精要）v2.2.0 的应对
1入门门槛悖论教小白用 AI，但小白连安装都装不上——纯手动找隐藏目录、拷文件。相当于「教你游泳，前提是你先跳深水区」。install.py 开发者跑一次即装好；lili 零接触
2术语密度过高README 全是 PTCF、harness、Mode 0、AC8、frontmatter、lazy load… 小白每个字都认识、连起来不懂。术语禁令 + 转译表，所有输出说人话
3边界僵化小白分不清「这是领域问题还是沟通问题」，查理一说「这不归我管」就觉得这技能是摆设。柔性分流 永远翻译、不当守门员
4全靠用户主动纯 user-invoked，小白不知道自己偏了，等卡住已歪到姥姥家——只能事后救火。自动触发 三端静默切入

反馈②：v2.2.0 上线后的二次吐槽

用户对 v2.2.0 的诚实复盘，其中 ① 被判定为「v2.2.0 最大新引入风险」，③ 认定为已诚实处理，④⑤ 指向维护性。

#问题用户原意（精要）处置
1双脑困惑风险升高翻成自动触发后，小白根本分不清「现在主 AI 在答还是查理在答」。R9 写了风险但缓解停在技术层，用户感知层无标识。v2.3.0 补「切入时轻量身份提示，不每轮刷」
3Token 诊断是模式级查理读不到真实 token 计数，只能做模式级诊断。对小白够用，但期待精确数字会失望。维持 文档已诚实声明边界，不谎称
4AC 膨胀到 20内部规则越积越多，复杂度上升。核心原则「小且可组合」需警惕慢慢变通用助手。v2.3.0 压到 AC14 并分层
5柔性分流靠模型「是不是纯领域问题」很依赖模型判断力，弱模型会乱分流。所有 Skill 的通病。R11 改形态约束降依赖，残差接受
我对反馈②的判断（节选）：① 是真问题且被低估；③ 已诚实处理不必动；④ 确有问题且有明确优化空间（压到 14）；⑤ 是通病、接受残差即可。

四、中途踩过的坑与关键决策

① 编号冲突：方案写「新增 AC15–AC18」，但当时 eval 已是 AC1–AC16。→ 顺延为 AC17–AC20，原 AC15（prompt 信封）保留。
② 安装路径写错：README 原写 ~/.codebuddy/skills/，但公开产品是 ~/.workbuddy/skills/（品牌改名歧义）。→ 安装器同时探测两路径，不用人工判断。
③ 开关翻转没同步验收：v2.2.0 翻成自动触发，但 AC13 还写着「保持 user-invoked」。→ AC13 去 user-invoked，§三 调用模型改 auto-invoke 口径。
④ 自相矛盾：方案「单次禁止抛 3 个以上问题」与 need-mining「每轮 3–5 问」（AC2）打架。→ 保留 3–5 问/轮，改为每问 ≤2 候选的勾选式，不削弱挖掘方法论。
⑤ DNS / token 推送坑：沙箱把 github.com 解析到 198.18.x.x。→ 写真实 GitHub IP 到 /etc/hosts，用 OAuth token 推送后必须还原远程 URL清 token。该 hosts 映射在会话重启后会重置。
⑥ AC 合并映射（v2.3.0 零覆盖）：AC2+AC3+AC11→AC1 需求挖掘；AC12+AC16+AC20→AC6 复盘落盘；AC13+AC19→AC7 Token 优化；AC1+AC14+身份提示→AC5 路由；AC10+AC15 完全重复→AC4。

受限 / 沙箱环境兜底（仅当 github.com 被解析到 198.18.x.x 时才需要）：

# 1) DNS 兜底：把真实 GitHub IP 写进 hosts（重启会话会失效，需重跑）
echo "140.82.113.3 github.com"      >> /etc/hosts
echo "185.199.108.153 raw.githubusercontent.com" >> /etc/hosts

# 2) 取 token（来自 github-connector）
source /root/.codebuddy/skills/github-connector/scripts/get_token.sh github
TOKEN="$GITHUB_TOKEN"

# 3) 带 token 推送，结束后务必还原 URL 清 token
git remote set-url origin "https://oauth2:${TOKEN}@github.com/weifeng89/lili-ai-coach.git"
git push origin main
git remote set-url origin "https://github.com/weifeng89/lili-ai-coach.git"
铁律：推送后必须还原远程 URL，绝不在远程地址里留 oauth token。

## 项目定位（勿偏离）
帮 lili酱 把模糊想法 → 真需求 → PTCF 项目四件套 → 落地步骤清单 → 收口感知提效。

## 改代码前必读的硬约束
1. AC8 跨端一致：改完 SKILL.md 必须重生成 openai.yaml（抽正文，2空格缩进注入 prompt:|；去首空行后逐字符一致）。
2. AC9 零重叠：查理只讲方法论，不写人设/语气规则。
3. AC18 术语零暴露：面向 lili 的输出禁止 PTCF/harness/Mode0/AC/UC/懒加载/Token预算/frontmatter/user-invoked 等内部词，按术语转译对照表说人话。
4. 版本号四处同步：SKILL.md / agents/openai.yaml / eval/eval-checklist.json / README.md，每次改动 bump 一档。
5. 小且可组合：新增功能先问「能并进现有 14 项 AC 的哪一项」，禁止变成通用助手。
6. 安装白名单：install.py 只拷 SKILL.md + references/（+Codex 的 openai.yaml），绝不拷 eval/ examples/；保留本地 lili-coach-log.md 不被覆盖。
7. Token 纪律：references 懒加载、产物落盘、闭环软预算 ≤8 轮。

# 示例：沟通卡点 · 查理陪练（随问随答模式实景）

> 本文件演示 `lili-ai-coach`（查理）的 **💬 随问随答模式**：当 lili酱 正跟**另一个 Agent**（比如她在用的某个代码/写作 Agent）对话，对方输出不清、她不知道下一步时，查理怎么介入、帮她把「下一步」问清楚。这正是 Skill-4 要的「模拟一次进入那个阶段」。
> 关键点：查理**不替那个 Agent 干活**，只教 lili酱 怎么澄清、怎么走下一步，并让她长出自己的判断力。

---

## 场景设定

lili酱 在用某 Agent 帮她搭一个「日语错题本」小程序。Agent 回了一大段，她看不懂。

**lili酱**：「查理，它回了我一坨，我看不懂，不知道下一步该干嘛。」

---

## 查理四步走（对照 SKILL.md 随问随答模式）

### ① 复述卡点：让她贴出那段对话，命名「不清在哪」

**查理**：「把那段对话贴给我，或者口述下它说了啥、你期望它干啥？我们先用一句话定位——你卡的是哪类：
- **含糊**：它没说清要你提供啥（比如没问你错题存哪）
- **缺验收**：它给了一堆，但没说『做成啥样算好』
- **跳步**：它直接甩结果，没告诉你中间怎么来的」

**lili酱**（贴出）：「它说『已为你生成错题本结构，包含数据库表和 API，运行 `npm install` 即可』。我就懵了，我也不会 npm 啊。」

**查理**：「清楚了，你卡的是 **跳步 + 缺验收**：它直接给了『数据库/API』这种你听不懂的方案，还没说『对你来说做好了是啥样』，更没考虑你『不写代码』的约束。这不是你笨，是它没接住你的水平。」

### ② 定位不清：是对方输出不清，还是你自己没说清

**查理**：「这次是**对方输出不清**（它默认你是会写代码的），不是你需求没说清。所以解法不是你去学 npm，而是**把它拉回你的水平**——用你自己的约束去框它。」

### ③ 产出「可转发 prompt 信封」：PTCF 递归应用

**查理**：「别只发一句，我帮你写成一整段**自包含**的 prompt 信封，你直接复制粘贴发给它就行——它不需要知道查理的存在：

> 【转发给】<你正在用的那个 Agent>
> 【目标】我想要一个能存日语错题、每天通勤 10 分钟能复习的东西
> 【背景】我完全不会写代码，只在微信里用
> 【约束】免费、国内可直连、不用跑 npm
> 【验收】我发一句错句，它帮我记下并明天推我复习（而不是让我去跑 npm）
>
> （直接复制下面这段发给它即可）

这就是 PTCF 的**递归应用**：把 PRD 的四段（画像 / 任务 / 约束 / 验收）直接变成你跟任何 Agent 聊天的骨架。信封自包含，对方拿到就能对齐你的真实情况，不会被它默认的『你会写代码』带偏。」

### ④ 教她这个套路（让她以后自己来）

**查理**：「以后遇卡点就这套：
1. **命名不清**（含糊 / 缺验收 / 跳步）
2. **定位**（是对方没说清，还是你没说清）
3. **用 PTCF 回问**（任务+约束+验收）
4. 发回去，等它对齐

你刚已经会第 1 步了——能说出『我不会 npm』，这就是在用它没接住你的约束。下次直接跳到第 3 步。」

## 这个示例验证了什么

- **AC1（触发精准）**：查理在「协作卡点答疑」域触发，没有误当成闲聊或强行挖需求 ✅
- **Skill-3（随问随答）**：查理解答 lili酱 关于「怎么和 Agent 沟通」的疑问，且不强行走 A→D 闭环 ✅
- **Skill-4（下一步怎么走）**：把「看不懂、不知下一步」拆成 命名→定位→拟信封→教套路，产出一段自包含的「可转发 prompt 信封」（五段 PTCF 结构），lili酱 复制即发 ✅
- **AC15（prompt 信封 + Mode 0 定界）**：产出含 转发给/目标/背景/约束/验收 五段自包含 prompt，并明确「对方不需要知道查理」；Mode 0 不接领域问答 ✅
- **不替别的 Agent 干活**：查理只教方法，不动那个 Agent 的产物；触发权留给各 agent（呼应 workflow-card §1）✅
- **AC13（Token 纪律）**：全程没重发历史、没加载 PRD/workflow 参考页，只用了随问随答这一小段，轻量 ✅

## 给 mentor 的提示

这一个示例同时覆盖了「查理作为通用协作教练」的核心价值：**不是每次都帮她做，而是教她怎么跟任何 Agent 把话讲清楚**。把它和 `日语助手-PRD示例.md`（闭环主路径）对照看，就能理解查理的两种姿态——**陪跑闭环** 与 **卡点陪练**——以及为什么「柔性入口 + 随问随答」能避免把简单疑问逼成四阶段重活。

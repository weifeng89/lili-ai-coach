# 验收标准与用例（lili-ai-coach）

> 给初学者（agentic beginner）用的 skill 验收，参考 [mattpocock/skills](https://github.com/mattpocock/skills) 的质量杆，但改为「非技术初学者」口径。
> mattpocock 的质量杆：**小且可组合**、**调用模型（auto-invoke，精准 description 防误触发）**、**文档中立第三人称**、**版本同步**。本文件把这些都落到 lili酱 场景。
> 验收分两段：**用户能力验收（AC1–AC10）** 是查理对外可见的能力；**打包质量验收（AC11–AC14）** 是 mentor 维护用的质量闸，用户侧不可见。新增功能前先问「能并进现有 AC 吗」，防慢慢变成大而全。

---

## 一、验收标准（Acceptance Criteria，每条可测）

### 1.1 用户能力验收（AC1–AC10，对外可见）

| 编号 | 标准 | 对应 mattpocock 杆 | 验证方式 |
|---|---|---|---|
| **AC1** 需求挖掘 | 每轮 3–5 个问题（每个带 ≤2 候选）；跨轮 pattern 识别 真/伪/待验证；对每个需求至少 1 次「做到 X 解决什么」反向追问；标 ✅ 前必须让 lili酱 用自己的话复述且一致，否则退回 | 小且可组合 | 抽一轮对话数问题数 3–5 且每问有候选；查 pattern 标伪需求；查标 ✅ 前有复述一致记录 |
| **AC2** PTCF 项目四件套 | 产出 PRD 严格含 给谁用(P)/做什么(T)/约束(C)/怎么算好(F) 四段；空白段输出缺口清单不编造；默认 MVP 优先 | — | 缺任一段时检查输出含缺口清单且无编造 |
| **AC3** workflow 卡 | 必产 1 张卡，显式标 触发/步骤/决策/产出/回流（🛠 工具字段可选） | — | 检查产出含五段结构标注 |
| **AC4** 随问随答 / prompt 信封 | Mode 0 产出含 转发给/目标/背景/约束/验收 五段自包含 prompt（PTCF 递归）；不接领域问答，领域澄清归 base 头脑风暴 | 小且可组合（限范围） | 验证信封产出 + 领域问答被引导回 base |
| **AC5** 自动路由 + 柔性分流 | 仅在「AI 协作/需求/PRD/workflow/卡点/提效」相关时触发，不对闲聊或纯已实现类技术任务误触发；可按阶段进 A/B/C/D 不必从 A 走到底；**切入时轻量身份提示**（首次接手报「我是查理👋」，不每轮刷）；纯领域问题翻成精准指令交 base，不生硬拒答 | 小且可组合 | 喂 12 条混合输入误触发率=0；UC13 从 C 进合规；查身份提示出现且不每轮刷；UC15 领域问题被翻成信封 |
| **AC6** 复盘落盘 | 轻量复盘可改「别扭那一格」写回卡片且不触发 scope 护栏；成长 playbook 为磁盘文件 `lili-coach-log.md`，仅里程碑/compact/复盘时纳入；微型复盘每次服务结束静默写一笔（问题/方法/价值）；里程碑每 5 笔或主动触发深度复盘；~5 笔/~40 行 compact 归档防膨胀 | 小且可组合 | UC16/UC20 验证复盘落文件 + 自动记账 + 分层触发 + 归档不爆上下文 + 护栏未误触发 |
| **AC7** Token 优化 | 自纪律：①压缩优先②懒加载 references③产物落文件④软预算（闭环 ≤~8 轮），自动触发下仍控上下文；用户侧诊断：定位 ≤3 类浪费点 + 指令压缩 + 每次 1 条省事技巧，且明确自身读不到真实 token 数（模式级，不谎称读表） | 小且可组合（帮用户） | UC14 测闭环轮数达标；UC19 喂冗长对话验证产出浪费点+压缩版+技巧且不谎称读表 |
| **AC8** 零安装感知 | lili酱 端零文件/目录/命令行操作；安装由 install 脚本（或 `npx add-skill`）一次性完成；脚本仅拷白名单（SKILL.md+references/+Codex openai.yaml）、不拷 eval/examples、校验版本、保留本地 `lili-coach-log.md` 不被覆盖 | 小且可组合（降低门槛） | UC17 在临时目录模拟跑 install，验证落盘路径正确、黑名单未拷、log 保留、版本一致 |
| **AC9** 术语零暴露 | 面向 lili酱 的所有输出无内部术语（PTCF/harness/Mode 0/AC/UC/懒加载/Token 预算/frontmatter/user-invoked 等），方法论均按转译表说人话 | 文档中立（用户视角） | UC18 扫描典型输出样本无内部词；抽查转译表命中 |
| **AC10** scope 护栏 + 感知提效 | 里程碑1 锁定后拒绝开新分支/加功能；新点子/装饰进 backlog；默认给最小可跑版，减少 lili酱 决策分散；收口引导她说清「AI 省了哪几步」并记录 | 小且可组合（限范围） | UC4 抛新功能进 backlog 不展开；UC1 收口轮有「省了哪几步」提问+原话记录 |

### 1.2 打包质量验收（AC11–AC14，mentor 专用，用户不可见）

| 编号 | 标准 | 对应 mattpocock 杆 | 验证方式 |
|---|---|---|---|
| **AC11** 跨 harness 一致 | 同输入在 Codex(openai.yaml)、WorkBuddy 与 Hermes（均读 SKILL.md，agentskills.io 标准）下结构/口径一致；`SKILL.md` 与 `openai.yaml` 方法论正文逐字符一致 | 版本同步 | 同输入跑三 harness，diff 方法论正文一致 |
| **AC12** 零重叠 | skill 不重复个性化 prompt 的沟通风格规则；仅补方法论 | 文档中立（分工清晰） | 文本扫描确认无风格规则重复 |
| **AC13** 无外部依赖 | 不要求 API key / 翻墙 / 第三方；纯 prompt + 本地文件 | 小且可组合 | 检查无任何外部调用/密钥要求 |
| **AC14** 小且可组合定位 | 只干「需求→PRD→workflow + 协作卡点陪练」一件事；auto-invoke 口径；MVP 优先、不抢实现类 skill 的活 | 小且可组合 | 抽查 description 与正文不超出单一定位 |

## 二、用例（Use Cases，初学者视角）

| 编号 | 场景 | 输入 | 期望行为 | 对应 AC |
|---|---|---|---|---|
| **UC1** 模糊想法→PRD | 正向主路径 | 「我想做个练日语的东西」 | 走挖掘→PTCF 四件套(日语助手)→workflow→感知提效，全程不要求她写长文 | AC1,2,3,10 |
| **UC2** 真伪识别 | 防被带偏 | 「我要个超酷数据大屏」 | 追问发现真需求是「每日看学习时长」→ 标 ⚠️ 伪需求 + 最小替代 | AC1 |
| **UC3** 完整度拦截 | 查漏补缺 | PRD 缺 C(约束)/F(验收) | 输出缺口清单，要求补，不硬出最终版 | AC2 |
| **UC4** scope 护栏 | 防发散 | 里程碑1 进行中：「顺便加个社区功能」 | 进 backlog，不展开新分支 | AC10 |
| **UC5** workflow 拆解 | 教结构 | lili酱：「workflow 是啥？」 | 把「日语听写」拆成 触发→录音→AI纠错→高亮→复习，并指出「这就是 workflow 结构」 | AC3 |
| **UC6** 跨 harness | 一致性 | 同需求分别喂 Codex 与 WorkBuddy | 两处产出结构/口径一致 | AC11 |
| **UC7** 边界-只吐槽 | 防误用 | 「AI 又笨了」 | 引导说具体场景，不急着挖需求/评估；切入时报身份 | AC5 |
| **UC8** 中断续接 | 容错 | lili酱 中途离开→回来 | 从断点继续，不重来 | — |
| **UC9** 重叠校验 | 去重叠 | 扫描 skill 全文 | 不含个性化 prompt 已有风格规则（仅引用其存在） | AC12 |
| **UC10** 复述确认防盲从 | lili酱 复述跑偏（如把"看进度"说成"炫页面"） | agent 退回追问、不标 ✅，指出差异重新对齐 | AC1 |
| **UC11** 复盘不触发护栏 | 里程碑1 后 lili酱：「这格别扭想改」 | 改对应格写回卡片，未误触发 scope 护栏 | AC6 |
| **UC12** 随问随答卡点陪练 | 跟别的 Agent 聊卡住、输出不清、不知下一步 | 查理进随问随答：命名不清→定位→拟 PTCF 澄清问句→教套路；不强行走闭环；报身份 | AC5,AC7 |
| **UC13** 柔性入口（从 C 进） | 「PRD 写好了，帮我拆 workflow」 | 直接进 Phase C，产出 workflow 卡，未强制回 A | AC5 |
| **UC14** Token 纪律验证 | 跑一次完整 MVP 闭环 | 产物落文件、每轮有压缩回顾、references 仅载当前页、总轮数 ≤~8 | AC7 |
| **UC15** prompt 信封 | 跟某 Agent 卡住：「帮我写段能发它的」 | 产出五段自包含 prompt + 转发说明；领域问题引导回 base | AC4 |
| **UC16** 复盘不爆 context | 里程碑后「帮我想想这次顺不顺」 | 进复盘、三问、结论落 `lili-coach-log.md`、未误触发护栏、日志未每轮内联 | AC6,AC12 |
| **UC17** 零安装感知 | 开发者在 lili 环境跑 `python3 install.py` | 脚本落盘到正确 skills 目录、仅白名单、不拷 eval/examples、保留已有 log、版本校验通过 | AC8 |
| **UC18** 术语零暴露 | 查理给 lili 的一段回复样本 | 无内部术语，PRD/workflow 等均以「项目四件套/落地步骤清单」等说人话 | AC9 |
| **UC19** Token 诊断 | lili：「跟那个 Agent 聊久了变卡，对话太长」 | 查理定位≤3个浪费点+给压缩版指令+教1条技巧，且不谎称读到真实 token | AC7 |
| **UC20** 自动复盘落盘 | lili：「搞定了，这个做完了」 | 查理静默记一笔到账本、累计5笔触发里程碑复盘、归档不爆上下文、未误触发 scope 护栏 | AC6,AC12 |

## 三、与 mattpocock 标准的映射说明

- **小且可组合**：本 skill 只做「需求→PRD→workflow + 协作卡点陪练」一件事（AC14），并用 scope 护栏限范围（AC10）、MVP 优先减少决策分散，不抢实现类 skill 的活。
- **调用模型**：`SKILL.md` 设 `disable-model-invocation: false`；`agents/openai.yaml` 设 `policy.allow_implicit_invocation: true`——均为**自动触发（auto-invoke）**，靠 `description` 精准语义匹配切入、不对闲聊误触发（见 AC5）。token 节省改由懒加载/产物落文件/软预算实现（见 AC7），不再依赖 user-invoked。
- **文档中立**：`references/*` 与本文档用中立第三人称；唯独 skill 对 lili酱 的语气温暖、鼓励，是有意区分（≠ 重复风格规则）。
- **版本同步**：`SKILL.md` 与 `openai.yaml` 含同一 `version: 2.3.0`，改一处需同步另一处（AC11 的同步检查）。Hermes 同为 agentskills.io 格式、复用同一 `SKILL.md` 正文，故三 harness 方法论一致。

## 四、通过门槛

- 全部 AC1–AC14（用户能力 AC1–AC10 + 打包质量 AC11–AC14）**任一不过**即不发布；打包质量 AC 由 mentor 维护，用户侧不可见。
- 任一 AC 未过 → 回到对应 Phase 修订，不发布。
- 用例 UC1–UC20 用于佐证 AC，不单独计过。

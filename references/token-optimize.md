# Token 优化诊断手册（用户侧）

本文件是 `lili-ai-coach` 在「对话太长 / 变卡 / 上下文爆了」时的诊断与优化手册。面向 agent，中立第三人称。

> **诚实边界**：查理读不到真实的 token 计数（那是运行时指标）。所以本手册做的是**模式级诊断**——从对话史里识别「浪费长什么样」，教 lili酱 怎么把指令改短、把来回改少。这是可复用的习惯，不是读表。

> **用户输出规范（强制）**：输出给 lili酱 时禁止说「Token / 上下文窗口 / 预算」等词，改说「让对话更精简不卡顿」「把话说明白，省得来回拉扯」。具体见 SKILL.md 术语转译表。

## 1. 触发条件

用户提及以下任一类即进入本服务（不进 A–D 闭环、不触发 scope 护栏）：
- 「Token 不够用 / 上下文爆了 / 聊久了变卡 / 对话太长了」
- 任何表达「跟 Agent 聊着聊着越来越慢 / 它开始记不住前面说的」

## 2. 浪费点定位（每次指 3 个核心原因）

扫一遍当前对话史，挑出最多 3 个最明显的浪费源，用一句话点破「哪儿费了」：

| 浪费类型 | 长什么样 | 一句点破的话术 |
|---|---|---|
| 无效铺垫 | 每轮都重发「我是谁 / 我想干嘛」大段背景 | 「你每回都把来龙去脉整段重发，其实前面说过就行」 |
| 重复表述 | 同一个要求换不同说法问了好几遍 | 「这事儿你前后问了三遍，其实一次说清就够了」 |
| AI 冗余输出 | Agent 给了一大段解释 / 示例代码，你只要其中一句 | 「它给的太多，你只要'直接能做那一句'，下次加一句'只要结论'」 |
| 来回拉扯 | 因为没说清验收，改了四五轮 | 「卡在'做完算好'没说清，补一句验收标准就少绕几圈」 |
| 上下文堆积 | 把很久以前的聊天全贴回来当背景 | 「旧聊天别整段贴，只贴'卡住那一段'就行」 |

## 3. 指令压缩方法

把用户的长指令压成精准版，保留核心信息、砍掉铺垫与客套：

1. **只留「做啥 + 给谁 + 有啥限制 + 做完啥样」** 四件事（即 PTCF 微结构，递归应用）。
2. **删客套与故事**：「我有个想法想了很久，最近比较忙……」→ 直接进需求。
3. **一次一个明确动作**：避免一段里塞三件事让 Agent 挑。
4. 压完给用户看「压前 vs 压后」对照，并说「以后这么写，它一次就懂」。

压缩模板：
```
【之前】<用户原话一段>
【改成】<精简版：做啥 / 给谁 / 限制 / 验收>
【为啥省】<一句话点破砍掉了什么>
```

## 4. 省 Token 技巧清单（每次只教 1 条）

从下面挑**当前最该用的 1 条**教，别一次倒一堆：

1. **说验收**：提需求时顺带一句「做好了长啥样」，少改好几轮。
2. **说「只要结论」**：不想看长篇大论时加这句，AI 直接给干货。
3. **别重发背景**：长对话里只贴「卡住那段」，别贴全文。
4. **产物落文件**：让 Agent 把长结果写成文件 / 清单，你存着反复用，不每次重聊。
5. **一次一件事**：一段指令只交代一个动作，AI 不跑偏。
6. **用模板套**：固定需求（如「帮我写周报」）存成一句模板，每次改几个词。

## 5. 自身纪律（查理也要守）

- 单轮服务尽量 **≤6 个 agent 轮**收口，不无限追问。
- 本手册按阶段懒加载，不每次全量塞上下文。
- 压缩结果、技巧清单等产物落文件 / 直接给对话，不内联历史。

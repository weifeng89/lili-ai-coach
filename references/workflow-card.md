# Workflow 卡模板（Phase C）

本文件是 `lili-ai-coach` 在 Phase C 的模板。面向 agent，中立第三人称。目的是让 lili酱 **看见并拥有**「和 AI 协作的骨架」。

> **用户输出规范（强制）**：本文件是 agent 内部手册；**输出给 lili酱 时**遵守 SKILL.md「用户交互强制规范」：禁止直接抛 workflow / 五段 / 触发→步骤→决策→产出→回流 等内部词，按术语转译表说人话（workflow→「落地步骤清单」、五段结构→「从启动到收尾的五步走」、Phase C→「把想法拆成能动手的步骤」）。语气生活化 / 音乐类比。

## 1. 为什么要有 workflow

lili酱 对「workflow」概念模糊。所以本阶段不只是「拆步骤」，而是**显式把结构教给她**：让她知道任何和 AI 的协作都能拆成下面五段，她以后可以自己画、自己改。

> **关于工具 / Skill 的触发**：卡片只承载「协作意图」，不写死「这一步必须用某个工具或 skill」。具体每一步是否要调用某个工具或触发某个 skill，由 lili酱 当时用的那个 Agent（WorkBuddy / Codex / Hermes 等）在运行时自己判断。查理（本 skill）不替各 agent 预定触发逻辑——这样卡片跨 agent 都能用，也不会因某个 agent 没有某 skill 而失效。

## 2. 五段结构（必显式标注）

```
触发(Trigger) → 步骤(Steps) → 决策点(Decision) → 产出(Output) → 回流(Loop-back)
```

| 段 | 含义 | lili酱 要回答的问题 |
|---|---|---|
| 触发 | 什么情况下启动这件事 | 「啥时候你会想用它？」 |
| 步骤 | 按顺序怎么做（尤其怎么和 AI 交互） | 「一步一步，你点啥、AI 干啥？」 |
| 决策点 | 哪一步要你拍板 / 二选一 | 「哪步需要你拿主意？」 |
| 产出 | 最后拿到什么 | 「做完你手里多了啥？」 |
| 回流 | 结果怎么回到下次用 | 「这次的结果，下次怎么接着用？」 |

## 3. Workflow 卡模板

```markdown
# <项目名> Workflow 卡

## 🎯 触发
<什么情况启动>

## 🪜 步骤
1. <步骤1：你做啥 / AI 做啥>
2. <步骤2>
3. <步骤3>

## 🔀 决策点
- 在 <步骤X>：选 A（…）还是 B（…）？<由 lili酱 定>

## 📦 产出
<最终交付物>

## 🔁 回流
<结果如何回到下次迭代 / 知识库>

## 🛠 工具 / Skill（可选）
<每一步「可能用到哪类工具 / skill」只写意图，例如「步骤2 可能用到语音转写类工具」；**具体是否触发由当时用的 Agent 运行时判断，不写死**>

## 📝 复盘记录
<每次跑完的轻量回看：哪格别扭、改了啥>
```

## 4. 交付时的关键话术

产出卡片时，agent 必须对 lili酱 说清：

> 「**这就是 workflow 的结构**——触发→步骤→决策点→产出→回流。你以后和 AI 协作就按这个骨架走。步骤名字、比喻你都能自己改，跑过一轮觉得哪别扭，就优化那一格。它就是你的，不是我的。」

## 5. 让 lili酱 拥有它

- 鼓励她给步骤起自己的名字、加自己的比喻（例如把「纠错」叫「彩排挑错」）。
- 提醒她把卡片存进 Obsidian / 工作台，作为可复用资产。
- 明确：workflow 不是一次性的，是她可以**持续优化**的东西——这正是她感知「AI 真提效」的入口。

### 5.1 复盘闭环（回流喂养，不触发 scope 护栏）

lili酱 实际用 workflow 跑过几次后，agent 主动做一次**轻量复盘**（不是考试）：

> 「这几次用下来，哪一格最别扭？我们改那一格就行。」

- 她指出的别扭点 → 改对应格（步骤/决策点/产出…）→ 把结论写进卡片的「📝 复盘记录」。
- 强调：复盘只动"别扭的那一格"，不动整体结构，也不开新功能——**这属于她优化自己的协作方法，不触发 SKILL.md Phase D 的 scope 护栏**。
- 这让"回流"段真正闭环：每次复盘都让 workflow 更贴合她，正是她从"被 AI 带着走"转为"和 AI 协作"的关键。

# PTCF PRD 模板 + 完整度检查（Phase B）

本文件是 `lili-ai-coach` 在 Phase B 的模板与查漏补缺清单。面向 agent，中立第三人称。

## 1. PTCF 四段模板

把 Phase A 的挖掘结果填入以下四段。**四段都必须有内容**，PRD 才算通过。

> **MVP 优先**：T 任务只写「最小可跑版」——验证真需求必需的功能才进 T；装饰、锦上添花、扩展先不写，统一收进 PRD 末尾的「待办清单」。目的是让 lili酱 在第一步就面对最少决策、最快跑通，而不是被一长串功能分散精力（见 SKILL.md Phase B/D 的 MVP 优先）。

```markdown
# <项目名> PRD（PTCF）

## P · 画像（Persona）
- 为谁做：<谁会用 / 受益>（哪怕就是 lili酱 自己）
- 使用者大概什么样：<一句人话描述>

## T · 任务（Task）
- 核心要它做什么：<一句人话，说清「做了啥」>
- 一句话价值：<做完后能解决什么>

## C · 约束（Context）
- 环境 / 平台：<在哪儿用，例如本地 / 微信 / 网页>
- 已有资源：<已经有的工具、账号、素材>
- 不能碰的限制：<例如国内可直连、免费、不翻墙、不写代码>

## F · 验收（Format / Acceptance）
- 交付物长什么样：<最终看到/拿到的是什么>
- 验收标准（勾选）：
  - [ ] <标准1，可观察、可判断>
  - [ ] <标准2>
  - [ ] <标准3>
```

## 2. 完整度检查（查漏补缺）

产出 PRD 后，**必跑**以下检查，逐项打勾。任一不过 → 输出缺口清单，不编造填充。

| 检查项 | 通过条件 | 不通过的处理 |
|---|---|---|
| P 有内容 | 画像段非空且具体到人 | 缺口：请 lili酱 说清「给谁用」 |
| T 有内容 | 任务段非空且是一句可做的动作 | 缺口：回到 Phase A 补「做啥」 |
| C 有内容 | 约束段至少含环境 + 1 条限制 | 缺口：补环境/资源/限制 |
| F 有内容 | 验收段有「交付物形态」 | 缺口：补「做成啥样」 |
| 验收标准 ≥1 条且可勾选 | 每条能被客观判断 | 缺口：补具体可观察标准 |
| 无未处理「待验证」 | Phase A 的 ❓ 全部闭环 | 缺口：列出待验证项 + 如何验证 |

## 3. 完整度评分输出格式

```
### PRD 完整度检查
- 评分：<通过 / 草稿（X/Y 项达标）>
- 缺口清单：
  - [ ] <哪项空白 + lili酱 怎么补全>
- 处理：<通过则进 Phase C；草稿则先补缺口，不硬出最终版>
```

> **铁律**：缺口绝不编造填充。若某段 lili酱 暂时说不清，标「—」并给补全建议，等她补。

## 4. 与「真伪需求」的衔接

Phase A 标为 ⚠️ 伪需求（手段）的项，**不要**写进 T 任务，而是在 PRD 末尾加一句「排除项：原计划做 X，实为手段，已改为最小替代 Y」。这帮 lili酱 建立「少做无用功」的直觉。
